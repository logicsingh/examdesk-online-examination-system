# Project Report Outline — ExamDesk

1. Title page (use the format required by your college).
2. Certificate, declaration and acknowledgement.
3. Abstract: problem, solution, technologies and verified outcome.
4. Introduction and problem statement.
5. Objectives, scope and user roles.
6. Existing versus proposed workflow.
7. Functional and non-functional requirements.
8. Architecture, use-case diagram, activity diagram and sequence diagram.
9. Database design: ER diagram, tables, keys and normalization.
10. Implementation: registration/login, role checks, exam authoring, timer, submission and scoring.
11. Testing: environment, test cases, actual results and known defects.
12. Screenshots from the real running application with captions.
13. Limitations, future work, conclusion and references.

## Suggested manual test cases

- Register a student and sign in.
- Try registering an already-used email.
- Verify students cannot open faculty or administrator routes.
- Create a draft exam and attempt to publish it without questions.
- Add questions and publish the exam.
- Submit correct, incorrect and unanswered options.
- Try starting the same exam a second time.
- Submit after the duration expires.
- Verify one student cannot view another student's results.
- Verify role changes take effect after signing in again.

Record observed outcomes; do not mark a test passed until you execute it.
